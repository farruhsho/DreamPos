# Localization how-to (for module work)

Spec: `docs/specs/localization.md` (decision D-024). Languages: **ru** (template, default), **uz**
(Latin, `oʻ gʻ` = U+02BB, `ʼ` = U+02BC), **ky** (Cyrillic, ң ө ү), **en**. No Tajik.

## Golden rule
The **ru value must be byte-identical to the Russian literal it replaces** (same «» quotes, dashes
— –, `№`, `…`, non-breaking spaces, trailing punctuation). Tests find widgets by Russian text.
Change only the text plumbing, never behaviour.

## Files
| What | Where |
|---|---|
| Your strings | `lib/l10n/src/<module>/ru.arb`, `uz.arb`, `ky.arb`, `en.arb` (all four, same keys) |
| Merged ARBs (generated, do not edit) | `lib/l10n/app_<lang>.arb` |
| Generated Dart (do not edit) | `lib/l10n/gen/*.dart` |
| Accessors | `lib/l10n/l10n.dart` (`context.l10n`, `L`) |
| Not-yet-migrated folders | `tool/l10n_pending.txt` |
| Legit Cyrillic literals | `tool/l10n_allow.txt` (or `// l10n-ignore` at the end of the line) |

`<module>` = `core`, `app`, `domain`, `auth`, or the folder name in `lib/features/<module>`.
A fragment is a flat JSON object: `{"posPayTitle": "Оплата", "posChange": "Сдача: {amount}"}`.

## Key naming
camelCase, starting with your module prefix followed by a capital letter (enforced by the merge):

| module | prefix | module | prefix |
|---|---|---|---|
| pos | `pos` | customers | `cust` |
| products | `prod` | dashboard | `dash` |
| inventory | `inv` | notifications | `notif` |
| purchasing | `pur` | sales | `sales` |
| settings | `settings` | shifts | `shift` |
| marketing | `mkt` | staff | `staff` |
| reports | `rep` | warranty | `warranty` |
| core | `common`, `core`, `pay`, `unit`, `role`, `lang` | app | `app`, `nav` |
| domain | `err`, `dom` | auth | `auth`, `setup` |

Name by meaning, not by text: `posPayButton`, `invReceiptPosted`, `repColumnRevenue`.
Never add keys to another module's fragment; reuse `common*` keys instead of duplicating them.
If a common word is missing, add a module key (`posCancelSale`) — do not edit `core`.

## Placeholders and plurals
- `{name}` placeholders; the merge infers types: **String** for plain `{x}`, **int** for a plural
  argument. Pass money/quantities/dates already formatted: `l.posChange(Money.format(c))`,
  numbers as `'$n'`. Placeholder names must be the same in all four languages.
- Optional metadata goes only in `ru.arb`: `"@posChange": {"description": "…"}`.
- Plurals (ICU): ru `{count, plural, one{{count} чек} few{{count} чека} many{{count} чеков} other{{count} чека}}`,
  en `one/other`, uz/ky just `other` (`{count, plural, other{{count} ta chek}}`).
- `pluralRu(...)` is deprecated for UI text: use `context.l10n.commonReceiptsCount(n)` etc. (or your
  own ICU key). Output in ru is identical (`5 чеков`).
- Quotes: «» in ru/ky, “ ” in en/uz. `№` in ru/ky/uz, `No.` in en. Keep labels short.

## Using strings
```dart
import '../../l10n/l10n.dart';            // relative path from your file

Text(context.l10n.commonSave)             // in widgets (rebuilds on language change)
throw BusinessException(L.current.errX);  // outside widgets: domain, PDF, CSV, notifications
L.receipt.corePrintTotal                  // printed receipt / gift slip / Z report (store setting)
L.forReceipt(settings)                    // same, from an already loaded settings map
Qty.format(q, unit, l)  Qty.unitLabel(unit, l)  paymentMethodLabel(m, l)  role.labelIn(l)
L.printable(text)                         // PDF/thermal text: maps ʻ ʼ to ‘ ’ (printer-safe)
l.staffMonth1 … l.staffMonth12           // month names (ARB keys, not intl; see below)
```
- Month and weekday names come from ARB keys (`staffMonth1..12`, the weekday keys used by
  `weekdayShortIn` in `reports/widgets/charts.dart`), not from intl `DateFormat`. This is a
  deliberate deviation from the spec: intl's ru standalone months are lower-case ("январь")
  while the UI shows "Январь", and the ARB keys let each language pick its usual form (ky keeps
  the Russian month names, as is common in Kyrgyzstan). There is no `initializeDateFormatting`
  call and no `L.dateLocale`; numeric `formatDate` / `formatDateTime` stay as they are.
- The bundled Roboto/RobotoMono fonts had no U+02BB (uz oʻ gʻ showed as boxes); it is mapped
  to their U+2018 glyph by `tool/patch_fonts_02bb.py` (noted in `assets/fonts/LICENSE-Roboto.txt`).
  Re-run it if the fonts are ever replaced.
- `const` widgets that held literals lose `const` (`Text(context.l10n.x)`); defaults that were
  string literals become nullable and resolve in `build` (see `SearchField.hint`, `QtyField.label`,
  `confirm(ok:, cancel:)`, `pickProduct(title:)`).
- Enums/const tables with labels: keep the value, add `String labelIn(AppLocalizations l)` and a
  `label` getter using `L.current` (see `Role`, `NavItem.labelOf`).
- `context.l10n` falls back to `L.current` (ru) when no delegate is present, so bare
  `MaterialApp(home: …)` tests keep working. `L` is reset to ru before every test
  (`test/flutter_test_config.dart`).
- Do **not** translate: user data (names), text already stored in the DB or written to it
  (movement reasons, audit details, ledger notes — allowlist them), currency symbols, demo seed.

## Commands
```sh
dart run tool/l10n_merge.dart                    # validate all fragments, merge, run gen-l10n
dart run tool/l10n_merge.dart --check            # validate only
dart run tool/l10n_check.dart --module pos       # Cyrillic literals left in lib/features/pos
dart run tool/l10n_check.dart --path lib/features/pos/widgets
dart run tool/l10n_check.dart                    # all of lib/ except pending folders (= the test)
flutter test test/l10n_check_test.dart
```
The merge is safe to run while other agents edit their fragments: runs are serialized with
`build/l10n_merge.lock`, gen-l10n runs in a temp dir and outputs are replaced atomically. If it
reports an error in someone else's fragment (e.g. a half-saved file), wait and re-run; fix only
your own fragment. Always run the merge after editing a fragment — the test fails when
`lib/l10n/app_*.arb` is stale.

## Finishing a module
1. `dart run tool/l10n_check.dart --module <m>` prints nothing but OK.
2. Delete the line `lib/features/<m>` from `tool/l10n_pending.txt` (only your line).
3. `dart run tool/l10n_merge.dart`, `flutter analyze` (0 issues), `flutter test` for your module and
   `test/l10n_check_test.dart`.
4. Optional: `SCREENSHOTS=1 SCREENSHOTS_LOCALE=uz flutter test test/ux/screenshots_test.dart`
   (files get a `_uz` suffix); check 390/1024/1440 for overflow in uz and ky.
